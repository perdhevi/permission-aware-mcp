## Verdict

The central claim holds: **the caller's identity, tenant and roles come only from
a verified bearer token plus the database, and every read is authorized inside the
same SQL statement that returns data.** No path was found where tool arguments,
request metadata or retrieved document text can change who the caller is or what
they can read. Every documented security boundary was confirmed in code and, where
practical, live. Findings below are low severity: one error-classification bug,
one recurring test-environment fragility, and minor ergonomics.

## Findings

### F1 — Low: symbol-only search queries are recorded as a service error

`search_knowledge` with a query such as `!!! ???` passes schema validation (it is
nonblank), but `HashEmbedder.EmbedQuery` returns "text has no searchable terms"
(`internal/rag/hash.go:35-36`). `Retriever.Search` returns that error unwrapped
(`internal/rag/retriever.go:31-33`), so `toolError` maps it to the default branch.

- **Client sees:** `resource service unavailable` (misleading; it is bad input).
- **Audit records:** `ERROR service_unavailable` instead of `DENY invalid_arguments`.
- **Impact:** no data exposure; operators may chase a phantom outage, and error
  rates are inflated by malformed input.
- **Reproduced live** on 2026-10-23.
- **Suggested fix:** in `Retriever.Search`, reject queries with no letter/number
  runes as `authz.ErrInvalidInput` before embedding, and add the case to
  `TestRetrieverBoundary`.

### F2 — Low: `TestLoginPKCECallback` depends on a fixed, often-occupied port

`cmd/login` hard-codes `127.0.0.1:8765` (`cmd/login/main.go:48`) and the test reuses
it. The test failed again today because an unrelated `python` process was
listening on 8765 — the third validation record in a row with this failure
(see [Phase 04](phase-04.md)). A real regression in that test would be easy to
dismiss as "the usual port issue".

- **Suggested fix:** let `run` accept the listener (or an address override used
  only by tests) and bind `127.0.0.1:0` in the test. The production redirect URI
  registered in Keycloak stays `:8765`.

### F3 — Low: `audit-disclosure-demo.ps1` leaves a nonzero `$LASTEXITCODE` after PASS

The script's final negative check intentionally runs a failing `psql` INSERT
(exit 3). When invoked in the current session (`& ./seed/audit-disclosure-demo.ps1`),
`$LASTEXITCODE` remains 3 after the PASS line, so a wrapper that checks it reports
failure. Behavior under `pwsh -File` was not checked here.

- **Suggested fix:** set `$global:LASTEXITCODE = 0` immediately before the
  final `Write-Output`.

### F4 — Info: PowerShell 7 is documented as required but is not installed here

The README read/search examples use `ConvertFrom-Json -AsHashtable`, which needs
PowerShell 7. `pwsh` is not on this machine's PATH. Both seed scripts **passed
under Windows PowerShell 5.1** today. Update 2026-10-25: the README read example
no longer uses `-AsHashtable` and runs on both 5.1 and 7.

### F5 — Info: HTTP access log omits the response status

`server.go:92` logs request ID, method and duration but not the status code, so
401 rejections are indistinguishable from successes in the operational log (they
also have no audit row, by design). Consider wrapping the `ResponseWriter` to log
the status.

### F6 — Info: redundant declaration in `cmd/server/main.go`

`var keyErr error` (line 43) is immediately shadowed by `key, keyErr := ...`
(line 44). Harmless; remove the `var` line.

### Accepted risks (already documented, re-confirmed)

These remain true and are stated in [security](security.md); they belong on the
limitations section of any demo or write-up:

- Development-only deployment: `APP_ENV=development` is enforced; no TLS, public
  Compose credentials, Keycloak in `start-dev`.
- Audit log is not tamper-resistant: the application's database role owns
  `audit_log`; no separate audit role, retention job or append-only trigger.
- Query hashes are unsalted SHA-256: common queries are guessable, so audit data
  is sensitive.
- An `ALLOW` row records the read decision, not proof of delivery.
- No rate limiting, token introspection or immediate token revocation (local
  user deactivation *is* immediate).
- `dev-hash-v1` is lexical, has no relevance threshold, and ranks with an exact
  scan (no ANN index). Document titles are not embedded — searching `salary`
  does not match Salary Guidelines' body text.
